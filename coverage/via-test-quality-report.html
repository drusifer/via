    Agent Instructions — Resolving Slow, Overlapping & Flaky Tests

    Follow this repeatable workflow when using this report to speed up and harden a test suite without losing validation coverage:

    1. Triage by Signal (Worst ROI First)

    1. SLOW + 0 COV — Confirm whether the test spawns an uninstrumented subprocess (enable coverage.py parallel = true, sigterm = true, patch = ["subprocess"], and per-test context propagation) or truly exercises no production code.
    2. SLOW + LOW — Inspect for blind time.sleep() calls, slow server shutdown loops (e.g. serve_forever(poll_interval=0.5)), repeated heavy DB/index/HTTP setup, or unnecessary disk SQLite I/O.
    3. SLOW + OVERLAP / SLOW + 0 UNIQ — Compare against the named faster neighbor and Asserts column. Never delete a test solely because Unique = 0; different assertions on the same branches still validate distinct contracts.
    4. MOCKS ONLY — Tests using mocks while covering 0 symbols in their imported project modules; check for hollow tests asserting only mock wiring.
    5. Smelly Asserts — Static AST checks for false-green tests: TAUTOLOGY (assert True / x == x), BROAD RAISES (pytest.raises(Exception) without match=), SWALLOWED ASSERT (assert inside broad try/except), CONDITIONAL ONLY (all assertions inside for/if with no non-empty guard), and NO ASSERTS (0 assertions).

    2. Apply Fixes in Order of Preference

    1. Prefer lower-resource equivalents: Test pure logic in-process with :memory: SQLite or direct function calls instead of booting HTTP servers or OS subprocesses when process boundaries are not under test.
    2. Replace blind sleeps with event-driven waits: Launch subprocesses unbuffered (python -u) and wait on a condition/log line (e.g. "Watching", "Re-indexed:") rather than fixed delays. If faster signaling exposes a startup race (such as logging ready before installing signal handlers), fix the production race rather than re-adding sleeps.
    3. Reuse expensive resources safely (prefer live sessions over pre-fetched snapshots): Share one scope="class" or scope="module" live server, session, indexed project, or daemon while keeping each test's actual request/operation inside the test body. Avoid pre-fetching multiple test responses into one snapshot dict in a fixture — snapshot fixtures attribute all coverage and setup failures to the first test and leave sibling tests with 0 covered symbols.
    4. Prevent shared-resource flakiness (mandatory): Only share fixtures across strictly read-only tests, OR isolate side effects using disjoint target files plus output-buffer slicing (mark() / output_since(mark)) so no test can pass on an earlier test's output. Keep mutating, lifecycle, and shutdown tests isolated per test.
    5. Delete only proven duplicates: Remove a test only when a faster test already covers the same branch arcs and checks the same assertions (confirm via AST review or targeted mutation testing on the covered functions).

    3. Verify Idempotently & Measure Before/After

    1. Run targeted modified files with --durations=15 and confirm zero failures and zero pytest deprecation warnings (use @classmethod under @pytest.fixture(scope="class")).
    2. Re-run the full self-contained, idempotent coverage pipeline (make test-coverage: clean .coverage* shards → via index . → pytest --cov-branch --cov-context=test → via coverage import-contexts → via coverage report).
    3. Confirm wall-clock time and flagged test counts dropped with 0% coverage loss and 0 regressions.
